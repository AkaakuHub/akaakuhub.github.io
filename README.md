# AkaakuHub

Three.jsで描画する部室を入口にした個人サイトです。室内では位置を固定し、四方の壁・天井・床へ視線を切り替えます。

## 部室

画面下部のボタンで四方の壁・天井・床を選びます。左右の矢印キー・横スワイプで壁を切り替え、上下の矢印キー・縦スワイプで天井と床を向きます。

ホワイトボードの紙はクリック・タップ、または「掲示を見る」で近づきます。「拡大」、マウスホイール、ピンチで実カメラを紙へ近づけ、拡大中はドラッグや矢印キーで紙面内を移動します。Escapeで全体表示に戻り、もう一度押すと部屋へ戻ります。別の紙へ移ると拡大を解除します。

卯辰山の緯度36.5732度・経度136.67774度と北方向180度の設定から、日付と実時刻における太陽・月の方位と高度をSunCalcで計算し、毎分更新します。座標と方位の設定は`src/scene/daylight/celestial.ts`で管理します。夜間は月光を太陽光と共通の方向光・影マップ・散乱処理へ渡し、壁・窓枠・家具による遮蔽を計算します。

月光は月の位相による明るさの変化と、距離の逆二乗による減衰を計算します。太陽と月は同じ地平線の可視率と大気減衰を使い、薄明から夜へ連続的に切り替えます。月が沈んだ後も、窓の天空光は弱い明るさを維持します。日付を剰余で巻き戻さず、実日時をそのまま天体計算へ渡します。

蛍光灯は天井の2基の器具と同じ位置に置いた矩形光源で照らします。ドア横のスイッチをクリック・タップすると、蛍光灯の光と管の発光をまとめてオン・オフできます。スイッチは自然光の設定を変更しないため、消灯しても窓からの太陽光・月光・天空光は残ります。

天空光は実際の窓ガラスの位置・寸法から矩形光源を作り、室内側へ照らします。色と明るさは太陽の高度と月光に合わせて更新します。蛍光灯と天空光の矩形光源には影マップを使わず、多重反射は計算しません。照明はリアルタイムで計算するため、形状・配置・材質を変更してそのまま確認できます。

チンダル現象の散乱光は通常の照明と同じ影マップを参照し、画面の深度から復元した物体の表面まで視線に沿って積分します。Henyey–Greenstein位相関数とBeer–Lambert則を使い、縦横をそれぞれ4分の1にした解像度で計算して、深度に応じて合成します。スマホは24ステップ、PCは48ステップを使い、合成時には再積分しません。[参考にした描画処理](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/rendering/scattering.hlsl)の原理をもとに、メートル単位の部室用GLSLとして実装しています。参照元の散乱係数0.000762/インチは0.03/メートルへ変換しています。

月光の位相・距離による減衰は[参照元の月光計算](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_moon.lua)、地平線と大気減衰は[共通の可視率計算](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_celestial_visibility.lua)に合わせています。参照元の表示用の強度比は転用せず、月光の基準照度は0.3lux、月のない夜の天空光は0.002luxとしています。[NPSの満月の照度範囲](https://www.nps.gov/subjects/nightskies/upload/FINAL_NPS_The_Power_of_Night_Handbook_lowres_508.pdf)と[夜空の照度の資料](https://parkplanning.nps.gov/showFile.cfm?projectID=60370&sfid=264018)を参考にしています。

消灯時の夜間露出はEV100=2、点灯時はEV100=7とし、昼はEV100=10へ補間します。これは画面上の見やすさを調整する表示設定です。外の空の色は露出を補正してから合成し、室内の消灯による露出変更で夜空まで白くなることを防ぎます。夜の青みも表示上の設定であり、測光値を保証するものではありません。

スマホとPCで同じ空間を描画し、画面の実寸に合わせて画角・描画解像度を調整します。

スマホとPCで共通の照明を使用します。反射プローブは5分間隔で更新し、操作していない間の連続描画は停止します。光の散乱には通常の描画で得た深度を再利用します。

床・壁・木材・布・金具には[Poly Haven](https://polyhaven.com/license)と[ambientCG](https://docs.ambientcg.com/license/)のCC0素材を使い、色・法線・粗さ・金属度を実寸で適用しています。支柱、蝶番、ビス、キャスター、窓やドアの金具も用途別の材質を共有します。素材の出典と著者は[素材一覧](public/materials/attribution.json)に記録しています。参考作品のモデルやテクスチャは使用していません。

画像は`src/assets/`へ集約し、ビルド時に内容に対応したファイル名で出力します。`manifest.json`には実ファイルのサイズとSHA-256を記録します。材質画像は約2.2MBです。最初に小さい起動用モジュールを読み込み、紙の画像が展開できた時点で部屋の組み立てを始めます。材質ごとにGPUの描画準備も並列で進め、画像と描画の準備が揃った物体から背景へ描画し、細い進捗バーと、準備が進むにつれて晴れるブラーを表示します。

取得・検証・共有・OPFS保存にはnpm版`unified-asset-loader@0.1.0`を使用します。マニフェストのSHA-256を取得元の識別に使い、素材を更新すると対象のキャッシュだけを入れ替えます。進捗は画像の展開とGPUへの転送が完了した件数から計算します。保存や展開に失敗した場合は読み込みを停止します。

## 開発

Node.js24.22.1以降とpnpmを使用します。HTTPSの証明書と秘密鍵を用意し、Git管理外の`.env.local`へパスを設定します。

```dotenv
DEV_TLS_CERT_FILE=/path/to/development.crt
DEV_TLS_KEY_FILE=/path/to/development.key
```

```sh
pnpm install
pnpm dev
```

アセットを追加・更新したときは、マニフェストを再生成します。

```sh
node scripts/assets/catalog.mjs
```

## 検証

```sh
pnpm check
pnpm build
```

Vite+、TypeScript、Oxfmt、Oxlint、Knip、Lefthookを使用しています。開発・プレビューはHTTPSで配信し、OPFS用Workerに必要なヘッダーを付与します。

本番の配信先にもHTTPSと次のレスポンスヘッダーが必要です。レスポンスヘッダーは配信側で設定します。

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```
