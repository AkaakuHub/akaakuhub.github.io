# AkaakuHub

Three.jsで描画する部室を入口にした個人サイトです。室内では位置を固定し、四方の壁・天井・床へ視線を切り替えます。

## 部室

画面下部のボタンで四方の壁・天井・床を選びます。左右の矢印キー・横スワイプで壁を切り替え、上下の矢印キー・縦スワイプで天井と床を向きます。

ホワイトボードの紙はクリック・タップ、または「掲示を見る」で近づきます。「拡大」、マウスホイール、ピンチで実カメラを紙へ近づけ、拡大中はドラッグや矢印キーで紙面内を移動します。Escapeで全体表示に戻り、もう一度押すと部屋へ戻ります。別の紙へ移ると拡大を解除します。

東京の代表座標である緯度35.6895度・経度139.69171度と北方向180度の設定から、実日時における太陽・月の方位と高度をSunCalcで計算し、毎分更新します。座標は`src/weather/schema.ts`、方位は`src/scene/daylight/celestial.ts`で管理します。画面の時計はAsia/Tokyoを使います。夜間は月光を太陽光と共通の方向光・影マップ・散乱処理へ渡し、壁・窓枠・家具による遮蔽を計算します。

天気は[Open-Meteoの現在天気API](https://open-meteo.com/en/docs)から、雲量・降水量・直達法線日射量・散乱日射量を取得します。これは気象モデルによる現在天気であり、建物の現地観測値ではありません。直射光には直達法線日射量、天空光には散乱日射量を使い、太陽高度によって日の出・日没付近を補間します。W/m²から描画用の光量への変換には0.12の係数を使います。雲量に応じた空の色と月光の減衰は近似です。月光の雲の透過率は1−雲量/100とし、全天が雲に覆われている場合は月の直接光を止めます。

月光は月の位相による明るさの変化と、距離の逆二乗による減衰を計算します。太陽と月は同じ地平線の可視率と大気減衰を使い、薄明から夜へ連続的に切り替えます。月が沈んだ後も、窓の天空光は弱い明るさを維持します。日付を剰余で巻き戻さず、実日時をそのまま天体計算へ渡します。

蛍光灯は天井の2基の器具と同じ位置に置いた矩形光源で照らします。ドア横のスイッチをクリック・タップすると、蛍光灯の光と管の発光をまとめてオン・オフできます。スイッチは自然光の設定を変更しないため、消灯しても窓からの太陽光・月光・天空光は残ります。

天空光は実際の窓ガラスの位置・寸法から矩形光源を作り、室内側へ照らします。色と明るさは太陽の高度と月光に合わせて更新します。蛍光灯と天空光の矩形光源には影マップを使わず、多重反射は計算しません。照明はリアルタイムで計算するため、形状・配置・材質を変更してそのまま確認できます。

チンダル現象の散乱光は通常の照明と同じ影マップを参照し、画面の深度から復元した物体の表面まで視線に沿って積分します。Henyey–Greenstein位相関数とBeer–Lambert則を使い、縦横をそれぞれ4分の1にした解像度で計算して、深度に応じて合成します。スマホは24ステップ、PCは48ステップを使い、合成時には再積分しません。[参考にした描画処理](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/rendering/scattering.hlsl)の原理をもとに、メートル単位の部室用GLSLとして実装しています。参照元の散乱係数0.000762/インチは0.03/メートルへ変換しています。

月光の位相・距離による減衰は[参照元の月光計算](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_moon.lua)、地平線と大気減衰は[共通の可視率計算](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_celestial_visibility.lua)に合わせています。[参照元の照明設定](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_lighting.lua)と同じく、月光の表示用の基準値を0.48、夜の天空光を0.16とし、天空光には月光の半分も加算します。これらは画面上の光量を決める値であり、luxへ校正した測光値ではありません。天空光の色も参照元と同じく、昼のRGB(190,210,255)から夜のRGB(100,145,235)へ補間します。

参照元と同じ固定露出の方式を使い、この部屋では昼間の既存設定であるEV100=10を維持します。時刻や照明スイッチによる露出変更は行いません。外の空の色と、室内を照らす天空光の色・強度は別に計算し、外景には露出補正を適用してから合成します。月光の増加で夜空の色まで白くしないための表示設定です。参照元と同じ最終画素や、実際の月光の測光値を保証するものではありません。

スマホとPCで同じ空間を描画し、画面の実寸に合わせて画角・描画解像度を調整します。

視点の移動中は縦横それぞれ半分の描画解像度と半分の散乱ステップ数を使い、停止時に通常の表示へ戻します。両方の描画バッファを読み込み中に準備し、視点を切り替えるたびに再確保しません。壁への回転は0.3秒、掲示への移動は0.4秒です。処理が遅れた場合も、実際の経過時間から視点を更新します。

スマホとPCで共通の照明を使用します。反射プローブは5分間隔で更新し、操作していない間の連続描画は停止します。光の散乱には通常の描画で得た深度を再利用します。

床・壁・木材・布・金具には[Poly Haven](https://polyhaven.com/license)と[ambientCG](https://docs.ambientcg.com/license/)のCC0素材を使い、色・法線・粗さ・金属度を実寸で適用しています。支柱、蝶番、ビス、キャスター、窓やドアの金具も用途別の材質を共有します。素材の出典と著者は[素材一覧](public/materials/attribution.json)に記録しています。参考作品のモデルやテクスチャは使用していません。

画像は`src/assets/`へ集約し、ビルド時に内容に対応したファイル名で出力します。`manifest.json`には実ファイルのサイズとSHA-256を記録します。材質画像は約2.2MBです。最初に小さい起動用モジュールを読み込み、紙の画像が展開できた時点で部屋の組み立てを始めます。材質ごとにGPUの描画準備も並列で進め、画像と描画の準備が揃った物体から背景へ描画し、細い進捗バーと、準備が進むにつれて晴れるブラーを表示します。

取得・検証・共有・OPFS保存にはnpm版`unified-asset-loader@0.1.0`を使用します。マニフェストのSHA-256を取得元の識別に使い、素材を更新すると対象のキャッシュだけを入れ替えます。進捗は画像の展開とGPUへの転送が完了した件数から計算します。保存や展開に失敗した場合は読み込みを停止します。

## 開発

Node.js24.22.1以降とpnpmを使用します。HTTPSの証明書と秘密鍵を用意し、Git管理外の`.env.local`へパスを設定します。

```dotenv
DEV_TLS_CERT_FILE=/path/to/development.crt
DEV_TLS_KEY_FILE=/path/to/development.key
```

```sh
pnpm install
pnpm dev:weather
pnpm dev
```

`pnpm dev:weather`と`pnpm dev`はそれぞれ別のターミナルで実行します。天気APIはローカルのWorkersランタイムで動き、HTTPSの開発サーバーから同一オリジンの`/api/weather`へ接続します。

## 天気APIとCloudflare Workers

`wrangler.jsonc`は`dist`の静的配信と`/api/weather`を設定しています。デプロイ時はビルド後にWranglerを使います。静的ファイルのクロスオリジン分離ヘッダーは`public/_headers`に定義しています。

- 外部の天気APIを呼ぶのはWorkerだけです。ブラウザーは有効期限が切れた場合に更新し、非表示の間は更新しません。失敗後も10分待ってから再試行します。
- 全アクセスで東京専用のDurable Objectを1つ共有し、同時取得を直列化します。取得開始前に次の取得可能時刻と試行回数を永続化します。
- 外部取得は最短10分間隔、UTCの1日につき最大144回です。失敗した取得も上限に含めます。オブジェクトの再起動で回数制限をリセットしません。
- 各配信拠点にも取得結果をキャッシュします。拠点のキャッシュを回避されても、共有オブジェクトの回数制限は維持されます。
- 座標や強制更新のクエリ、GET以外のメソッドは受け付けません。取得先URLは東京に固定しています。
- 取得できない場合は503とRetry-Afterを返し、晴天の値で代用しません。画面には更新失敗を表示します。

この制限は外部天気APIの呼び出し数を抑えるものです。Workerへのリクエスト自体や、DoS攻撃によるCloudflareの処理費用をなくすものではありません。

アセットを追加・更新したときは、マニフェストを再生成します。

```sh
node scripts/assets/catalog.mjs
```

## 検証

```sh
pnpm check
pnpm build
```

Vite+、TypeScript、Oxfmt、Oxlint、Knip、Lefthookを使用しています。開発・プレビューはHTTPSで配信し、OPFS用Workerに必要なヘッダーを付与します。

本番の配信先にもHTTPSと次のレスポンスヘッダーが必要です。レスポンスヘッダーは配信側で設定します。

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```
