# AkaakuHub

Three.jsで描画する部室を入口にした個人サイトです。室内では位置を固定し、四方の壁・天井へ視線を切り替えます。

## 部室

左右の矢印キー・横スワイプで壁を切り替え、上の矢印キー・下向きの縦スワイプで天井を向きます。天井からは下の矢印キー・上向きの縦スワイプで壁へ戻ります。床向きの視点はありません。部屋のロゴ・全画面ボタン・移動ボタンは画面に重ねません。

最初はプロフィールの紙へ着目した状態で始まります。ホイールまたはスワイプでプロフィール・GitHub・記事の順に移動し、最後の記事からさらに進めると部屋へ戻ります。5秒間部屋へ戻らなければ、紙の外を押す案内を白い文字で表示します。Escapeと紙の外側のクリック・タップでも戻ります。拡大後のピンチ操作とドラッグは紙内の拡大・移動に使います。部屋を見渡す状態だけ、移動可能な方向の画面の辺にLucideのシェブロンを表示します。天井から戻る下方向以外に床向きの視点はありません。ライセンスはpublic/icons/lucide-LICENSE.txtへ同梱しています。

ホワイトボードの左上には、名前とGitHubの現在のアイコンを印刷したプロフィール用紙を表示します。アイコンはGitHubの画像URLから取得します。「好きなこと」「趣味」「好きな言語」「ひとこと」の4欄は空欄で、記入用の余白を残します。左下には手書き風の「GitHub」と草の掲示用紙を配置します。草は指定のSVGをフロントから取得し、室内の光と影を反映します。アニメーションは一度だけ再生し、視点移動やズームではリセットしません。右側には手書き風の「最新記事」とブログの最新記事2件を表示します。記事の紙はOGP画像を切り抜かず、縦横比を保って全体を収め、日付とリンクを下端へ印字します。各紙へ近づいてもう一度クリックするか、右上のリンクを押すと対象を開きます。右下にはOpen-Meteoのクレジットを表示します。

読み込み画面は、部屋の形を描いたCSSのアニメーションと実際の進捗を表示します。初期HTMLにスタイルを埋め込み、3Dのコードや画像を待たずに読み込み中だと伝えます。進捗は小数点以下2桁で表示し、桁と小数点の幅を固定します。読み込み中の工程説明や公開情報は置きません。3D用のCSSは部室のコードと一緒に読み込みます。

初回フレームを描画した次の画面更新で読み込み表示を閉じます。表示の完了判定ではGPU全体の処理待ちを行いません。進捗は巻き戻さず、失敗時も取得済みの進捗を維持します。ロード完了後の通常処理のエラーでは読み込み表示を再表示しません。HDRの表示は300msで立ち上げ、露出・光源・最終的なHDRの明るさは維持します。動きを減らす設定では立ち上がりのアニメーションを省きます。画面用と反射用のシェーダー準備は並列に進め、GitHubアイコンの取得は部室のコードを読む前に始めます。

エラーの詳細はコンソールへ記録し、お客さまの画面には表示しません。初回ロードの失敗やGPUとの接続切れで、ページを自動リロードする処理はありません。失敗時は読み込みアニメーションを停止し、「再読み込み」ボタンを表示します。ボタンを押した場合だけページを再読み込みします。GPUとの接続が切れた後は描画も停止します。サーバー側の取得回数制限は維持します。

PCケースはクリック・タップ、または窓の方向にある「PCを見る」で斜め前の拡大視点へ移動します。ホイール・ピンチ・「拡大」で近づき、拡大中はドラッグで表示範囲を動かします。戻るボタンやEscapeで元の部屋の向きへ戻ります。操作対象の判定には描画しない単純な形状を使い、マウス移動時には部屋全体との交差を計算しません。

PC正面下部の3D電源ボタンで起動・終了します。起動中はファンが回り、モニターが点灯して室内へ光を投げます。光源は常に保持し、電源では強度だけを変えます。PCとモニターのクリック判定は個別の範囲に分け、両者の間やモニター外側を押すと着目を解除します。デスクライトはモニターの左に置き、かさを天板から約55cmの高さにしています。ドア横の照明スイッチも3Dモデルを直接操作します。スイッチの両脇には緑色の蓄光テープを模した薄い発光素材を貼り、消灯後も位置を示します。追加の光源は使いません。モニターのリポジトリ一覧と、その取得用GitHub API・README APIは廃止しました。

地点は千代田区千代田1-1-1付近に固定しています。[国土地理院の住所検索](https://msearch.gsi.go.jp/address-search/AddressSearch?q=東京都千代田区千代田1-1-1)が返す千代田1番の代表点、緯度35.683659度・経度139.754089度を使います。個人の住所や端末の位置情報は取得しません。この座標と北方向180度の設定から、実日時における太陽・月の方位と高度をSunCalcで計算し、毎分更新します。座標は`src/weather/schema.ts`、方位は`src/scene/daylight/celestial.ts`で管理します。画面の時計はAsia/Tokyoを使います。夜間は月光を太陽光と共通の方向光・影マップ・散乱処理へ渡し、壁・窓枠・家具による遮蔽を計算します。

天気は[Open-Meteoの時間別予報API](https://open-meteo.com/en/docs)から、雲量・降水量・直達法線日射量・散乱日射量を日本時間の1日につき1回取得します。当日0時から翌日0時までの25点を共有キャッシュし、毎分、現在時刻を挟む2点を線形補間して照明を更新します。これはその日の最初の取得時点の気象モデル予報であり、その後の予報更新や現地観測を追跡しません。直射光には直達法線日射量、天空光には散乱日射量を使い、太陽高度によって日の出・日没付近を補間します。W/m²から描画用の光量への変換には0.12の係数を使います。雲量に応じた空の色と月光の減衰は近似です。月光の雲の透過率は1−雲量/100とし、全天が雲に覆われている場合は月の直接光を止めます。

同じ1回のリクエストに天気コード・雨・にわか雨・降雪・地上10mの風速と風向も含めます。雨と雪は窓の外だけに描画し、室内の深度で壁や家具の裏を隠します。降水量によって雨粒の数・太さ・長さ・不透明度・落下速度を変えます。粒子の位置はGPUで計算し、風向・風速に合わせて流します。雨と雪の密度・落下速度は表示用の近似で、風は室内へ吹き込みません。

降水量と降雪量はAPIの「直前1時間の合計」という定義に合わせ、現在の時間帯の終了時刻にある値を使います。雲量・日射・風は時刻間を補間し、風は向きを角度のまま補間せず、水平成分へ変換して補間します。雨と雪が視野外にある場合は連続描画を止めます。これらの表示更新のために外部APIを追加で呼び出すことはありません。

月光は月の位相による明るさの変化と、距離の逆二乗による減衰を計算します。太陽と月は同じ地平線の可視率と大気減衰を使い、薄明から夜へ連続的に切り替えます。月が沈んだ後も、窓の天空光は弱い明るさを維持します。日付を剰余で巻き戻さず、実日時をそのまま天体計算へ渡します。

蛍光灯は天井の2基の器具と同じ位置に置いた矩形光源で照らします。ドア横のスイッチをクリック・タップすると、蛍光灯の光と管の発光をまとめてオン・オフできます。スイッチは自然光の設定を変更しないため、消灯しても窓からの太陽光・月光・天空光は残ります。

蛍光灯には、通常の明るさから最大±0.15%だけ連続的に変化する揺らぎを加えます。管の発光と矩形光源の強さを同じ割合で変え、天空光と露出は変えません。管が画面内にあるときだけ100ms間隔で更新し、反射用の環境マップは毎回生成しません。管が画面外にある場合と動きを減らす設定では通常の明るさへ戻し、消灯中と非表示タブでは追加の描画を行いません。これは微弱な揺らぎの演出で、特定の安定器の波形を実測して再現したものではありません。

天空光は窓列全体の位置・寸法から1つの矩形光源を作り、室内側へ照らします。窓枠ごとの天空光の遮蔽は計算しない近似です。蛍光灯2基には512四方の影マップを1枚ずつ持たせ、床全体を投影して接地部分の影を計算します。形状の変更時だけ影を更新し、蛍光灯の微弱な揺らぎでは作り直しません。矩形光源の位置・放射量・LTCによる光の分布は維持します。影は灯具の中心から投影する近似で、面全体からの正確な軟影ではありません。太陽光と蛍光灯の影は、受光面の深度勾配に合わせてPCFの比較深度を補正し、傾いた紙などの自己遮蔽の縞を抑えます。サンプル数は5回を維持します。多重反射は計算しません。照明はリアルタイムで計算するため、形状・配置・材質を変更してそのまま確認できます。

チンダル現象の散乱光は通常の照明と同じ影マップを参照し、画面の深度から復元した物体の表面まで視線に沿って積分します。Henyey–Greenstein位相関数とBeer–Lambert則を使い、縦横をそれぞれ4分の1にした解像度で計算して、深度に応じて合成します。スマホは24ステップ、PCは48ステップを使い、合成時には再積分しません。[参考にした描画処理](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/rendering/scattering.hlsl)の原理をもとに、メートル単位の部室用WGSLとして実装しています。現在の室内用の消散係数は0.003/メートルです。これは実測した空気の値ではなく、室内全体が白い霞で覆われる状態を抑えるための描画設定です。

月光の位相・距離による減衰は[参照元の月光計算](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_moon.lua)、地平線と大気減衰は[共通の可視率計算](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_celestial_visibility.lua)に合わせています。[参照元の照明設定](https://github.com/AkaakuHub/steamvr-workshop-tools-win/blob/main/scripts/vscripts/stage03_lighting.lua)と同じく、月光の表示用の基準値を0.48、夜の天空光を0.16とし、天空光には月光の半分も加算します。これらは画面上の光量を決める値であり、luxへ校正した測光値ではありません。天空光の色も参照元と同じく、昼のRGB(190,210,255)から夜のRGB(100,145,235)へ補間します。

参照元と同じ固定露出の方式を使い、この部屋ではEV100=7を使います。蛍光灯の光束は1本3,350lmです。時刻や照明スイッチによる露出変更は行いません。外の空の色と、室内を照らす天空光の色・強度は別に計算し、外景には露出補正を適用してから合成します。月光の増加で夜空の色まで白くしないための表示設定です。参照元と同じ最終画素や、実際の月光の測光値を保証するものではありません。

スマホとPCで同じ空間をWebGPUで描画し、画面の実寸に合わせて画角・描画解像度を調整します。中間バッファと画面出力には16bit浮動小数点を使い、画面を`rgba16float`・`toneMapping: extended`で構成します。Extended sRGBで通常の白を超える値を保持し、HDR画面では発光部分へ最大4倍の表示範囲を割り当てます。SDR画面では同じ描画経路で通常の表示範囲へ収めます。実際の最大輝度は端末・OS・画面の設定に依存します。iPhoneではWebGPUのHDR出力に対応するSafari 26以降が必要です。

描画上限はスマホで150万画素、PCで300万画素、ピクセル比の上限は2です。視点の移動中にも同じ画素数と散乱処理を使い、明るさが切り替わらないようにします。反射プローブは移動中の更新を見送ります。天体光の影マップはスマホで1024四方、PCで2048四方です。壁への回転は0.6秒、掲示への移動は0.36秒です。処理が遅れた場合も、実際の経過時間から視点を更新します。

静止した部材は材質と1.5mごとの領域で結合し、視野外の領域を描画対象から外します。共有する形状の頂点結合は一度だけ行います。視点・照明・掲示内容・画面サイズが変わらない間は室内の色と深度を再利用し、雨や雪だけを重ねます。光の散乱も同じ深度と照明を使う間は積分結果を再利用します。

動的部材や天気が映らない画角では、保存したHDR色と深度を別の全面バッファへコピーせず、そのまま合成へ渡します。露出とHDRの色変換を済ませたsRGB画像へFXAAを適用し、静止した合成結果も再利用します。最終出力は公式RenderPipelineを使い、追加の自動色変換バッファーと深度バッファーを作りません。

スマホとPCで共通の照明を使用します。反射プローブは5分間隔で更新し、操作していない間の連続描画は停止します。光の散乱には通常の描画で得た深度を再利用します。

反射の有無によってシェーダーの構成を切り替えず、取得中も通常表示にはPMREMノードを使います。反射の撮影は同じ部材を参照する専用シーンで行い、その環境光はゼロに固定します。通常シーンの環境光ノードを切り替えず、更新先の反射テクスチャを撮影シーンからサンプリングしません。部材の形状・材質・光源は共有し、反射の描画先は1枚を再利用します。反射の撮影時は間接光の寄与をゼロにして、以前と同じ1回の反射を計算します。材質と頂点属性の構成が同じ部材のシェーダー準備は一度だけ行います。Three.js 0.186.1には[GPU準備のパッチ](patches/three@0.186.1.patch)を適用し、ノードの構築順を維持したままGPUパイプラインの完了をまとめて待ちます。メインスレッドは12msを目安に処理を譲ります。Three.jsを更新する際は、このパッチの適用と描画結果を確認します。

初回表示の目標はキャッシュなしで2秒以内です。`performance.getEntriesByName('room-first-frame')`で、ナビゲーション開始から初回の描画命令の送信までを確認できます。開発時は同じ値をコンソールにも記録します。ネットワークを含む実ブラウザーでの2秒以内の達成は未確認です。

床・壁・木材・布・金具には[Poly Haven](https://polyhaven.com/license)と[ambientCG](https://docs.ambientcg.com/license/)のCC0素材を使います。壁と天井にはPainted Plaster Wallの写真にある汚れ、アルミにはMetal050Bの擦り傷と粗さ、塗装金具にはPaintedMetal001の塗装の擦れを適用します。塗装の元画像は無彩色化し、金属度に応じて塗膜だけに部材の塗装色を乗算します。露出した地金は元画像の中性色を維持します。壁と塗装金具の色画像は1024px、凹凸画像は512pxとし、汚れの明度差を弱めます。部材ごとにUVの切り出し位置を変え、同じ傷が同じ位置に並ばないようにします。粗さと金属度は1枚に格納し、法線画像と合わせて共有します。描画用の形状やパスは追加しません。ホワイトボードの筆記面には塗装の汚れを適用しません。支柱、蝶番、ビス、キャスター、窓やドアの金具も用途別の材質を共有します。素材の出典と著者は[素材一覧](public/materials/attribution.json)に記録しています。参考作品のモデルやテクスチャは使用していません。金具の追加画像は`node scripts/assets/surface-wear.mjs`で再生成します。

画像は`src/assets/`へ集約し、ビルド時に内容に対応したファイル名で出力します。`manifest.json`には実ファイルのサイズとSHA-256を記録します。材質画像は約1.53MBです。起動用モジュールから取得を始め、3DコードとGPUの初期化を並行して進めます。取得済みのバイト列は同じ読み込み処理内でデコーダーへ渡し、二重取得・二重のキャッシュ読み出しを行いません。展開後は保持していた参照を解放し、失敗時は残りの取得と待機中のデコードを中断します。最初に必要な紙とフォントが揃うと部屋を組み立てます。草とブログ画像の取得は初回描画後に始めます。色画像と法線画像は寸法を維持してWebP圧縮し、粗さとAOの値は変更せず未使用チャンネルだけを除去します。再圧縮には`node scripts/assets/packed-surfaces.mjs`と`node scripts/assets/texture-encoding.mjs`を使います。

矩形光源のLTC参照表はThree.jsの数値をそのまま描画で使用する16bit浮動小数点の65,536バイトのバイナリへ変換して配信し、JavaScriptの大きな配列の解析を省きます。実行時の32bitから16bitへの変換を省き、以前と同じ値のテクスチャ2枚を生成します。これは材質の反射を計算する参照表であり、部屋の形状・光量・照明位置を記録したライトベイクではありません。[ライセンス](public/lighting/LICENSE.txt)を同梱しています。Three.jsの更新後は次の順に再生成します。

```sh
node scripts/assets/lighting.mjs
node scripts/assets/catalog.mjs
```

取得・検証・共有・OPFS保存にはnpm版`unified-asset-loader@0.1.1`を使用します。マニフェストのSHA-256を取得元の識別に使い、素材を更新すると対象のキャッシュだけを入れ替えます。進捗は画像の展開とGPUへの転送が完了した件数から計算します。保存や展開に失敗した場合は読み込みを停止します。

## 開発

Node.js24.22.1以降とpnpmを使用します。HTTPSの証明書と秘密鍵を用意し、Git管理外の`.env.local`へパスを設定します。

```dotenv
DEV_TLS_CERT_FILE=/path/to/development.crt
DEV_TLS_KEY_FILE=/path/to/development.key
```

```sh
pnpm install
pnpm dev:weather
pnpm dev
```

`pnpm dev:weather`と`pnpm dev`はそれぞれ別のターミナルで実行します。天気APIはローカルのWorkersランタイムで動き、HTTPSの開発サーバーから同一オリジンの`/api/weather`へ接続します。

スマートフォンで読み込みを確認するときは、開発用モジュールの転送を避けるため、`pnpm build`の後に`pnpm preview --host 0.0.0.0 --port 5174 --strictPort`で本番ビルドを配信します。開発サーバーは先に停止し、天気APIのサーバーは起動したままにします。

## 天気APIとCloudflare Workers

`wrangler.jsonc`は`dist`の静的配信と`/api/weather`を設定しています。`pnpm exec wrangler deploy`では、デプロイ前に`pnpm build`を自動実行します。生成や圧縮に失敗するとデプロイを停止します。静的ファイルのクロスオリジン分離ヘッダーは`public/_headers`に定義しています。

Cloudflare Workers Buildsを使う場合は、管理画面のBuild commandに`pnpm build`を設定します。このサービスはWranglerのカスタムビルド設定を使用しないためです。[Cloudflareの設定仕様](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)に従い、CIでも同じビルドを実行します。

- 外部の天気APIを呼ぶのはWorkerだけです。ブラウザーは翌日の日本時間0時までキャッシュを使い、非表示の間は更新しません。取得に失敗した場合も、翌日になるまで自動再試行しません。
- 全アクセスで東京専用のDurable Objectを1つ共有し、同時取得を直列化します。取得開始前に次の取得可能時刻と試行回数を永続化します。
- 外部取得は全ユーザーを合算して日本時間の1日につき最大1回です。日付が変わった後の最初の要求で取得し、失敗した取得も1回に数えます。オブジェクトの再起動で回数制限をリセットしません。
- 各配信拠点にも取得結果をキャッシュします。拠点のキャッシュを回避されても、共有オブジェクトの回数制限は維持されます。
- 座標や強制更新のクエリ、GET以外のメソッドは受け付けません。取得先URLは東京に固定しています。
- 取得できない場合は503とRetry-Afterを返し、晴天の値で代用しません。画面には更新失敗を表示します。

この制限は外部天気APIの呼び出し数を抑えるものです。Workerへのリクエスト自体や、DoS攻撃によるCloudflareの処理費用をなくすものではありません。

## ブログ

ブログのRSSをWorkerで取得し、最新記事2件とサムネイルを掲示します。専用のDurable Objectで元のRSSと次の取得可能時刻を永続化し、全来訪者を合算して24時間に最大1回に制限します。失敗も1回に数え、同時取得を直列化します。キャッシュ切れ後に取得できなければ503を返します。掲示の取得に失敗しても部屋の表示・操作は維持します。GitHubの草は公開SVGを直接読み込みます。

## フォント

Google FontsのZen Maru GothicをWOFF2で同梱しています。500の1種類に絞り、初期掲示に必要な文字は約23KBの1ファイルにまとめています。操作案内などで追加の文字が必要になったときだけ、`unicode-range`で122分割したフォント定義を読み込み、該当する文字のファイルを取得します。記事のタイトルはOGP画像に含まれるため、そのタイトル用のフォントは取得しません。フォントCSSは初期HTMLの描画を待たせずに読み込み、掲示用紙を描く前に必要な文字のフォントを準備します。ビルド後のフォント・CSS・画像は内容に対応した名前になり、`/assets/*`を1年間キャッシュします。ライセンスは`public/fonts/OFL.txt`に同梱しています。再取得には`node scripts/assets/fonts.mjs`と`node scripts/assets/board-text-font.mjs`を使います。

ホワイトボードの見出しにはGoogle FontsのYomogiを使います。「最新記事」「GitHub」「Skills」に必要な文字だけをWOFF2で同梱し、実行時にGoogle Fontsへ接続しません。再取得には`node scripts/assets/board-font.mjs`を使います。ライセンスは`public/fonts/yomogi-OFL.txt`に同梱しています。

`pnpm build`では、元の材質・照明データから2個の配信ファイルとマニフェストを毎回自動生成します。紙と照明の先行分を分け、画像のバイト列と寸法を維持します。材質の追加は`src/assets/materials.ts`へ登録し、対応する元画像を配置します。元画像の変更後に配信ファイルを手動で再生成する必要はありません。内容が同じ生成ファイルは書き換えません。

JavaScript・CSSはViteが最小化し、ビルドが確定したファイルからBrotliの圧縮データを自動生成します。3Dコードの先読みURLとアセットのキャッシュ用ハッシュもビルド結果に合わせて更新します。`pnpm preview`は対応するブラウザーへBrotliを配信します。本番のCloudflareでは[配信側の圧縮](https://developers.cloudflare.com/speed/optimization/content/compression/)が適用されます。

## 環境音

雨・窓に当たる雨・雨樋・風のCC0実録音を重ね、既存の天気予報の降水量・風速・風向で音量を変えます。雨の基本音はAMB Rain Loop 2のFLAC原音から、風は屋内から収録したWind from inside #1のWAVから生成します。鳥声が含まれるテラスの録音は昼用の別レイヤーに分離し、東京の太陽高度と日の出からの経過時間で調整します。朝は日中より大きく、日没後は停止します。強い雨風では昼用レイヤーを抑えます。追加の天気APIは呼びません。出典は[音源一覧](public/audio/sources.json)に記録しています。配信はモノラル48kHzのOpusで192kbpsを指定し、必要な音源だけ初回描画後にunified-asset-loaderで取得・検証・保存します。

ブラウザーの再生許可に従い、最初のクリック・タップ・キー操作で音声を開始します。左下の音声アイコン、Mキー、Tabで選択できる音声操作から切り替えられます。音はアクセスのたびにオフで始まります。3Dの表示完了から5秒後、左下の音・モーションボタンを指すLucideの矢印と、両方を紹介する案内を初回だけ表示します。モーション非対応端末では音だけを案内します。表示済みの記録はlocalStorageの1項目へ保存し、次回以降は表示しません。両方をオンにしている場合も表示しません。非表示中は停止し、視点の変更ではループを再開始しません。位置による音量・方向の変化と短い残響を加えます。音声はinteractiveの遅延設定を使い、聴取位置と向きは現在の補間値から50msの線形補間でカメラへ追従します。マスターゲインは2、雨の最大レイヤーゲインは1とし、瞬間的なピークはコンプレッサーで抑えます。残響は実測した室内音響ではありません。再生成にはFFmpegをPATHへ設定し、node scripts/assets/weather-audio.mjsを実行します。

モーション操作はアクセスのたびにオフで始まります。権限APIを持つタッチ端末、または有効な姿勢センサー値を取得できた端末にだけ、音ボタンの横へモーションボタンを表示します。オンにする操作から姿勢センサーの権限を要求し、許可後の姿勢を基準にします。横画面では軸を補正し、回転やタブの切り替え時には基準を取り直します。視点の移動は最大約2.5cm、傾きは各軸1.5〜4度に制限し、オフにすると元の視点へ戻します。センサー値とオン・オフ状態は保存しません。

スマートフォンなどタッチ操作の端末では、音・モーションボタンを60px、アイコンを28pxに拡大し、ボタン間を12px空けます。案内の矢印もボタンの大きさと位置に合わせて配置します。

角丸部材と金具は頂点を共有してからWorkerへ渡します。角丸の形状・法線・UVは保ち、同じ寸法の部材はジオメトリーを共有します。収納の木製棚板・引き出し・天板には0.7〜1.5mmの平らな面取りを使い、1枚44三角形で端部の反射を表現します。本の表紙やホワイトボードの丸みは維持します。

天体光の影は、影を落とす実際の部材の範囲を光源側の座標へ投影し、影カメラの範囲とバイアスを調整します。影マップの解像度は変えません。無塗装の金属とゴムには追加のコーティング計算を使わず、樹脂・すりガラスの指定した粗さを別の粗さマップで意図せず小さくしないようにします。陶器の釉薬やカーテンの反射は維持します。

天体光の散乱は、視点・投影・光源・影の深度が変わったときだけ計算します。蛍光灯の明るさや記事画像だけを更新するときは再利用します。PCや草が画面外にある場合は、それらの追加描画を省きます。

塗装金具は既存のARM画像の青チャンネルから、塗装が剥がれて露出した金属を区別します。木材・壁・金具の法線は元のスキャンの傾きを保ち、見切りと窓台は元の粗さの変化を使います。ガラスは追加の透過用画面コピーを行わず、薄板の両面反射を視線の角度から計算します。蛍光管とモニターの発光面は直接光ですでに計算されるため、反射プローブへの二重計上を除きます。最初の反射が完成した時点で、初期化用の黒い反射バッファーを破棄します。

同一形状の金具はインスタンスで共有し、複数形状が混じる金具は一つのメッシュへ結合して描画回数を維持します。キーキャップは形と寸法で共有し、複製のために角丸や押し出し形状のコンストラクターを再実行しません。形状・法線・UV・三角形数は維持します。
描画器のノード変換は`src/scene/rendering/node-library.ts`で、使用する基本・標準・物理材質と平行・矩形光源だけを登録します。未使用の材質・光源・トーンマッピングの実装はビルドから除きます。別の通常材質や光源を追加するときは、この登録と変換テストも更新してください。直接使うノード材質は登録不要です。PMREM内部の基本材質、影、HDRの合成経路は維持します。
